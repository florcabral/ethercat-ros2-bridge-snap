What we achieved

We produced an installable Ubuntu 26.04 snap that packages the EtherCAT userspace and ROS 2 bridge needed for the EasyCAT demo. The snap uses the IgH kernel modules supplied by the host and accesses the host-created /dev/EtherCAT* device instead of attempting to ship kernel modules.

The final artifact is ethercat-ros2-bridge_0.1_amd64.snap. It was built on July 20, 2026 with strict confinement.

Main packaged components

  • IgH EtherCAT 1.6.9 userspace library and command-line tool
  • ICube ROS 2 EtherCAT driver
  • ROS 2 Lyrical and ROS 2 Control runtime
  • Controller manager and joint-state broadcaster
  • Complete EasyCAT process-data configuration
  • A ROS adapter that publishes both analog inputs on /joint_states
  • A live terminal dashboard for the presentation

EasyCAT integration

The complete 32-byte output and 32-byte input process images are configured.

ItemConfiguration
Vendor ID0x0000079a
Product ID0x00defede
RxPDO0x1600, object 0x0005, 32 bytes
TxPDO0x1a00, object 0x0006, 32 bytes
SyncManagersSM0 output; SM1 input

The first two input bytes become A0 and A1. The adapter publishes them as a standard sensor_msgs/msg/JointState message:

  1. easycat_analog_0
  2. easycat_analog_1

This allows PlotJuggler, Foxglove, and normal ROS 2 command-line tools to consume the data.

Demo experience

The complete demo starts with one command:

snap run ethercat-ros2-bridge.demo

It starts the EtherCAT bridge in the background and displays a clean dashboard containing numeric A0/A1 values and live bar graphs. At the same time, both values are published on /joint_states.

ROS launch output is kept out of the presentation terminal and written to:

~/snap/ethercat-ros2-bridge/current/easycat-demo.log
Presentation options: the basic demo needs only the terminal. The extended demo can show the terminal, PlotJuggler or Foxglove, and a webcam view of the board together in one screen recording.

Compatibility and confinement work

The ICube Jazzy driver required a small compatibility layer to build against ROS 2 Lyrical. The upstream revision remains pinned, while the Lyrical-specific CMake changes are stored as separate reviewable files.

Packaged ROS applications use Fast DDS over UDPv4. This avoids shared-memory permission errors under strict confinement while allowing a host visualization tool to discover /joint_states.

Device access is restricted to /dev/EtherCAT[0-9]* through a custom-device interface. Local installation works; Snap Store publication and automatic connection will require review because this is a super-privileged interface.

Validation completed

The snap was installed and exercised in a clean Ubuntu 26.04 virtual machine. Validation confirmed:

  • Strict snap installation and interface connection
  • The pinned IgH 1.6.9 command-line runtime
  • ROS discovery of the EasyCAT package, ICube driver, and broadcaster
  • Successful parsing of the packaged launch description
  • Correct loading of the full 32+32-byte EasyCAT configuration
  • Successful startup of the one-command dashboard
  • End-to-end conversion from EasyCAT-style input to /joint_states

A synthetic message containing A0=42 and A1=211 produced these exact ROS values:

name: [easycat_analog_0, easycat_analog_1]
position: [42.0, 211.0]

The earlier bare-metal hardware test also confirmed that the EasyCAT board works with IgH when the host receive timeout is set to 5000 microseconds.
